Google 授權改版：延遲授權與群組逐人授權

不再用 Google 授權擋下使用者的第一則訊息。agent 真的碰到 Google 工具沒 token 時，router 才在回覆裡放授權連結；使用者授權完，router 自動把剛才的問題重跑一次並推播答案。群組裡每一回合一律以發話者的身分執行 Google 工具，授權連結也只給發話者。

狀態 設計定案，實作中 日期 2026-09-18 文字版計畫 docs/google-auth-per-member-plan.md

為什麼要改

現在的 gate 只認房間。每一則訊息進 agent 前先檢查這個房間有沒有 Google token，沒有就把訊息擋下來、只回一則授權連結。這帶來兩個問題：

  • 個人聊天室：跟 Google 無關的功能（讀 PDF、上網查資料、翻譯）也被擋住，使用者第一次接觸就被要求授權，授權完還得把問題再打一次。
  • 群組：token 屬於群組本身，不屬於任何一位成員。連結廣播給全群，誰點誰的 Google 帳號就成了群組的帳號，第二個人點會靜默覆蓋。之後所有成員都能透過助理讀那個人的 Gmail、改他的行事曆。這不只是體驗問題，是隱私漏洞。

身分規則只有一條

群組回合的成員 key 是發話者的 LINE userId；個人聊天室的成員就是房間本身。兩種房間走同一條程式路徑，個人房間只是每次都換到同一個檔案。

群組裡沒加官方帳號好友的成員，LINE 不會給 userId。這種人的 Google 工具一律失敗，助理回「LINE 沒提供你的身分，請先加我為好友再試」，不給連結。

機制

每回合換 token 檔

三個 Google MCP 都把 token 路徑寫死在容器的 /opt/google-workspace/tokens.json，帳號 key 也寫死在 config.yaml。這兩樣都動不了，但路徑背後的檔案可以換。Router 在每回合開始前，把 tokens.json 這個 symlink 指向當前發話者的成員檔。已驗證三個 MCP 每次工具呼叫都重新讀檔，所以換檔不需要重啟容器。

授權連結怎麼回到使用者手上

Router 只看得到 agent 的最終回覆，看不到工具呼叫的錯誤。所以沿用 task9 的做法：工具回報沒 token 時，agent 在回覆裡放一個固定字串 google-auth://request，router 在回覆出口把它換成「這個房間、這回合發話者」的授權連結。這個字串不是秘密，別人觸發也只會拿到自己的連結。

  • gmail 與 drive 是自己寫的 MCP，錯誤文字直接含這個字串和「原樣單獨放一行」的指示。
  • calendar 是第三方套件，錯誤文字不可控，靠 system prompt 的規則補上：任何 Google 工具回報未授權，就放這個字串。

授權完成後自動接續

資料佈局

data/<room>/google/
  gcp-oauth.keys.json                 不變
  gcp-oauth.keys.installed.json       不變
  tokens.json → members/<member_key>.json    相對 symlink，指向當前發話者
  members/
    <member_key>.json                 { "<account_key(room)>": { access_token, refresh_token, expiry_date, … } }

data/<room>/router_state/pending_auth/
  <member_key>.json                   等授權完成要重跑的 InboundMessage
既有房間遷移tokens.json 是一般檔案時，搬成 members/<account_key(room)>.json。個人房間的成員 key 正好等於它，授權無縫延續；群組房間這個 key 沒人會用到，舊 token 等於作廢，成員各自重新授權。
換檔的原子性建 temp symlink 再 rename 蓋過去。成員檔用 temp 加 rename 寫入。MCP 刷新 token 會整檔覆寫，透過 symlink 落在正確的成員檔。
換檔時機只在房間的 turn lock 內、回合開始前。回合進行中絕不換，避免 MCP 的讀改寫把 A 的 token 寫進 B 的檔。
Gate 的去留blocked 狀態和 GOOGLE_OAUTH_GATE 設定刪除，只留「已授權但缺 Drive 權限」的提醒。暖機改由加好友與加入群組事件觸發，比現在更早。

已驗證的事實

事實對設計的影響
calendar MCP 2.6.2 每次工具呼叫都重新讀檔、重設憑證；gmail 與 drive 每次呼叫都 open()回合之間換檔即可，不用重啟容器或 MCP
calendar MCP 把檔案裡所有 key 當帳號集合；gmail 與 drive 嚴格用 GOOGLE_ACCOUNT_MODE成員檔內層只放一個 key，維持房間的 account_key
換入的 entry 必須含 access_token，否則 calendar 視為沒帳號callback 寫入時一定含 access_token（現行已如此）
MCP 刷新後整檔覆寫；calendar 在 fallback 路徑遇到壞 JSON 會刪檔成員檔原子寫入；換檔只在回合之間
calendar 依名稱找行事曆有 5 分鐘快取，key 是帳號集合同 key 換人後 5 分鐘內用名稱找行事曆可能對到前一人；primary 與含 @ 的 id 不受影響。v1 接受，寫進 troubleshooting
/opt/google-workspace 是整個目錄 rw bind mounthost 端換 symlink 容器立即可見；symlink 目標用相對路徑
InboundMessage 是 pydantic model；process_inbound 對訊息無副作用pending 可直接序列化存檔、原樣重跑

已知限制

群組裡別人可以點 A 的連結

Google 的 callback 拿不到 LINE 身分。B 點了 A 的連結並用 B 的 Google 登入，token 會被存成 A 的。第一版靠「連結點名 A」和「A 已完成授權」的公告讓誤綁看得見，擋不住。後續可加開關把連結改推到 A 的私訊：能拿到 A 的 userId 就代表 A 已加好友，一定推得到。

  • 公告只寫 LINE 顯示名稱，不含 Google email。要顯示 email 得多要一個 scope。
  • 「找大家共同空檔」這類跨成員需求刻意不支援：那需要多個成員的 token 同時在場。將來可由 router 對每位成員各跑一回合再彙整。
  • API channel（TUI、開發測試）沒有人可以推播，授權完成後的 pending 直接丟棄。
